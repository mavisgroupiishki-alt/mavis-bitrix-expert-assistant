# v76 — финальная ежемесячная сверка оригиналов актов

## Зафиксированные правила

1. Месяц сверки определяется только по `CLOSEDATE` успешно закрытой сделки в воронке «Производство». Слова «Июль», «Август» и т.п. в названии задачи на акт не меняют месяц отчёта.
2. CRM-привязка `UF_CRM_TASK = D_<ID сделки>` имеет абсолютный приоритет. Поиск по названию используется только если актовая задача не имеет прямой связи со сделкой.
3. В проекте «Акты счета» в сверке учитываются только задачи, название которых начинается с `АКТ`. Договоры, счета и счёт-заказы исключаются.
4. Если по резервному поиску по названию найдено несколько актовых задач, сделка попадает в «Нужно проверить вручную», а не в «Актов нет».
5. В отчёте используется полное название услуги из сделки. Если две строки внутри одного эксперта совпадают полностью, к ним добавляется ID сделки.

## Автозапуск

- `ACTS_RECON_AUTO_ENABLED` — по умолчанию `true`.
- Проверка выполняется каждые 30 минут (`ACTS_RECON_CHECK_MINUTES`).
- В последний рабочий день месяца по правилу Пн–Пт после 18:00 Минска (`ACTS_RECON_SEND_HOUR_MINSK=18`) строится отчёт за текущий месяц.
- Получатель: Татьяна Куровская, Bitrix user ID 2182 (можно переопределить `ACTS_RECON_LEADER_ID`).
- Перед отправкой ИИгорь читает последние сообщения личного диалога с Таней и проверяет, не был ли уже отправлен отчёт с тем же заголовком. При невозможности проверить дубль автоматическая отправка пропускается.

## Ручной тест

Старый endpoint сохраняется:
`/api/acts/reconcile?month=2026-08&send=0&token=...`

`send=1` отправляет отчёт Тане вручную, но также проверяет дубль.
