# v89 — CJM Бобик запускается до общей очереди

Исправлена причина, по которой тестовая сделка 38072 могла не получить «Ход работы» даже в no-call режиме.

## Причина
v88 сначала получала список сделок стадии с ограничением 50 и затем последовательно обрабатывала их. Тестовая сделка могла:
- не попасть в первые 50;
- ждать завершения долгих STT retry на других сделках.

## Исправление
- В начале каждого polling-цикла `CJM_TEST_DEAL_ID` загружается напрямую через `crm.deal.get`.
- Если это Производство и сделка находится на целевой стадии, она запускается первой, до общей очереди.
- Для 38072 старый in-memory DONE очищается перед тестовым прогоном; таймлайн-защита по конкретному NO_CALL activity остаётся от дублей после успеха.
- Добавлены диагностические логи `[autopilot-test]` с точной причиной, если тест не стартует.

Остальная массовая логика Производства, акты, push, incoming, блоки 5–6 не менялись.
