# Локальное приложение Bitrix24 «Возврат оригиналов»

Добавлено в существующий `mavis-bitrix-expert-assistant` без изменения логики автоотправки актов/договоров.

## Что появится

После деплоя и переустановки локального приложения в Bitrix24 в группе **Приложения** левого меню появится пункт **Возврат оригиналов**.

Страница открывается внутри Bitrix24 и не требует отдельного пароля. Авторизация выполняется через текущую OAuth-сессию пользователя Bitrix24 (`BX24.getAuth`), а сервер проверяет её вызовом `user.current`.

## Адреса

- основной обработчик существующего приложения: `/`
- установка: `/install`
- новый отчёт: `/doc-return-report`

Для Render:

- `https://mavis-bitrix-expert-assistant.onrender.com/`
- `https://mavis-bitrix-expert-assistant.onrender.com/install`
- `https://mavis-bitrix-expert-assistant.onrender.com/doc-return-report`

## Права локального приложения

Оставьте все права, которые уже нужны текущему ИИ-ассистенту, и убедитесь, что включены:

- `placement` — встраивание приложения в меню;
- `task` — задачи и история стадий;
- `crm` — сделки и компании;
- `user` (или user_basic/user_brief, если портал предлагает версии) — имена ответственных.

## Обязательные переменные Render

Новых обязательных секретов для отчёта нет. Он использует существующий `BITRIX_WEBHOOK_URL` для серверной выборки данных и OAuth текущего пользователя для проверки доступа.

Уже должен быть настроен:

```text
BITRIX_WEBHOOK_URL=https://mavisgroup.bitrix24.by/rest/.../...
```

## Необязательные настройки

```text
DOC_RETURN_REPORT_PROJECT_ID=36
DOC_RETURN_REPORT_ARCHIVE_STAGE_ID=264
DOC_RETURN_REPORT_PORTAL_DOMAIN=mavisgroup.bitrix24.by
DOC_RETURN_REPORT_CACHE_SECONDS=300
DOC_RETURN_REPORT_ALLOWED_USER_IDS=2110,2210
```

`DOC_RETURN_REPORT_ALLOWED_USER_IDS` оставьте пустым, если доступом должны управлять стандартные настройки доступа к локальному приложению в Bitrix24.

## Логика отчёта

- **Вернулось** = задача находится на стадии `Архив` (`264`).
- **Не вернулось** = любая другая стадия проекта #36.
- По умолчанию интерфейс показывает документы, созданные в **2026 году**.
- Можно выбрать другой год, месяц, произвольный диапазон дат, компанию, эксперта, текущую стадию, тип документа и просрочку.
- Фильтрация после первой загрузки выполняется в браузере и не делает отдельный запрос к Bitrix24 на каждый график.
- Серверный результат кэшируется на 5 минут (настраивается через `DOC_RETURN_REPORT_CACHE_SECONDS`). Кнопка **Обновить данные** принудительно обновляет кэш.

## Интерактивность

- список компаний уникальный;
- клик по компании раскрывает все её невозвращённые документы;
- у каждого документа есть кнопка **Открыть** и **История стадий**;
- история стадий загружается только по выбранной задаче, поэтому не тормозит основную страницу;
- доступна выгрузка текущей отфильтрованной выборки в CSV.

## Как обновить

1. Загрузить содержимое этого проекта в существующий GitHub-репозиторий.
2. Дождаться автоматического Deploy в Render.
3. В Bitrix24 открыть настройки локального приложения.
4. Проверить права `placement`, `task`, `crm`, `user`.
5. Путь обработчика оставить на корень Render (`/`).
6. Путь первоначальной установки оставить `/install`.
7. Выполнить **Переустановить приложение** / повторную установку.
8. Страница установки автоматически зарегистрирует:
   - вкладку `ИИ-ассистент` в сделке;
   - `Возврат оригиналов` в `LEFT_MENU`.
9. Открыть в левом меню Bitrix24 группу **Приложения → Возврат оригиналов**.

## Безопасность

Страница отчёта не принимает отдельный публичный пароль и не отдаёт секрет входящего вебхука в браузер. API отчёта принимает OAuth-токен текущего пользователя из iframe Bitrix24 и перед отдачей данных проверяет его через `user.current` на домене `mavisgroup.bitrix24.by`.
