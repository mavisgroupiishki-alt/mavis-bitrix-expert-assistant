# v106 — Возврат оригиналов: EMAIL ONLY / backlog / manual queue

Что исправлено:

- Процесс возврата оригиналов использует **только email**. Поле «предпочитаемый способ связи», Viber и Telegram к этому процессу не относятся.
- Письмо **никогда не отправляется без реального вложения**. Нужен скачиваемый DOC/DOCX/PDF (существующий механизм скачивания из задачи/старых комментариев).
- Подпись содержит номер `+375333315898`.
- Тема письма: `Срочно! Возврат оригинала!`.
- Ошибки данных (нет email, нет/не скачивается файл, внутренний email MAVIS) переводят задачу в существующую стадию `Ручная отправка` и добавляют понятный комментарий.
- Стадия `Ручная отправка` больше не создаётся через REST: код только находит уже созданную вручную стадию, поэтому не нужны права на `task.stages.add`.
- Очередь ускорена и не может быть случайно заторможена старыми переменными Render:
  - polling раз в 1 минуту;
  - минимум 10 действий за цикл;
  - минимум 60 проверок за цикл;
  - минимум 3 задачи параллельно.
- Исторический хвост `Отправлены` включён в backlog mode.
- Старые задачи, которые уже до автоматизации стояли в `Эл. Почта`, по-прежнему защищены от слепой повторной отправки.
- POST webhook для возврата оригиналов принудительно выключен. Единственный источник отправки — polling, чтобы не было дублей.
- Дефолтная тестовая задача отключена (`DOC_RETURN_TEST_TASK_ID` пустой по умолчанию).

Проверка после deploy в Render Logs:

`[doc-return] v106 EMAIL_ONLY active: ... maxActions=10 ... maxChecks=60 ... concurrency=3 ...`

При успешной отправке:

`[doc-return] SENT #1 ... file=<имя файла> ... dedupe=v106-email-only`
