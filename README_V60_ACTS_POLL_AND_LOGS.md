# v60 — Акты: polling стадии + понятные логи

Что исправлено:

1. `tasks.task.list` теперь корректно читает ответ Bitrix в формате `{ tasks: [...] }`.
2. `/api/acts/task-done` пишет в Render Logs сам факт вызова и результат отправки.
3. Добавлен резервный polling проекта «Акты счета» (по умолчанию каждые 60 секунд). Он автоматически ищет стадию с названием «Сделано/Сделаны» через `task.stages.get`.
4. В пилотном режиме polling обрабатывает только задачи, привязанные к `EXECUTOR_TEST_DEAL_ID` / `LIVE_CHAT_TEST_DEAL_ID`, поэтому старые клиентские задачи массово не отправятся.
5. Автопилот теперь делает первый цикл сразу после старта.
6. В стартовых логах явно выводится версия v60 и состояние основных флагов.

Опциональные переменные Render:

- `ACTS_DONE_POLL_ENABLED=true` (по умолчанию true)
- `ACTS_DONE_POLL_INTERVAL_SECONDS=60`
- `ACTS_DONE_STAGE_ID=` можно оставить пустым: стадия определяется по названию «Сделано/Сделаны».

Для пилота должно быть:

- `EXECUTOR_TEST_DEAL_ID=34946`
- `EXECUTOR_ALL_DEALS=false`
- `ACTS_SEND_TO_CLIENT_ENABLED=true`
- `BITRIX_WEBHOOK_URL=...`
- для Viber: `WAZZUP_API_KEY` и `WAZZUP_VIBER_CHANNEL_ID`

7. Повторный тест больше не блокируется старым маркером `[MAVIS_ACTS_TASK_DONE]`: дедупликация идёт только по `[MAVIS_ACTS_SENT]`, который ставится после успешной отправки.
