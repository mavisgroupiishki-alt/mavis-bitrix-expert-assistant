# Технический план Визуально подписанный акт PDF

**Спека:** [spec.md](spec.md)  **Создан:** 2026-11-11

## Технологии

Node.js, существующий `adm-zip`, временный каталог ОС и LibreOffice `soffice`. Внешний конвертер не используется: он потребовал бы новый секрет и передачу актов третьей стороне.

## Архитектура

`actsHandleTaskDone` скачивает выбранный DOCX и передаёт его новому модулю подписи. Модуль копирует встроенное изображение штампа в DOCX, добавляет floating-изображение за текстом у абзаца «М.П.», вызывает `soffice` в изолированном временном каталоге и возвращает PDF-буфер. Актовая отправка всегда использует SMTP для такого PDF, чтобы не прикладывать исходный DOCX из Bitrix Disk.

## API / Интерфейсы

- `createSignedActPdf({ source, stamp, sofficePath })` → `{ buffer, fileName }` либо точная ошибка; никогда не возвращает частичный PDF.
- `ACTS_SIGNATURE_ENABLED=true` включает контур.
- `ACTS_SIGNATURE_SOFFICE_PATH` задаёт путь к `soffice`; по умолчанию `soffice`.
- `ACTS_SIGNATURE_ANCHOR_TEXT=М.П.` задаёт обязательный якорь.

## Риски

- В Render может отсутствовать LibreOffice. Контур завершится безопасной ошибкой; перед деплоем потребуется установить бинарный файл.
- Разные шаблоны актов могут не содержать «М.П.». Это не допускает угадывания координат и требует ручной отправки.
- Визуальный штамп не подтверждает юридическую КЭП.
