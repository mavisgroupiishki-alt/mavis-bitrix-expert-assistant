# v78 — CJM блоки 3–4

## Блок 3. Первое касание + контроль дедлайна документов

Исправлено:
- напоминание эксперту через 4 рабочих часа считается от `MOVED_TIME` стадии «Эксперт назначен» по Минску;
- старый звонок до назначения эксперта больше не закрывает контроль;
- известный звонок короче 60 секунд не считается полноценным первым касанием;
- для короткого теста можно задать `FIRST_CALL_TEST_MINUTES=2`;
- после успешной отправки «Хода работы» ИИ сохраняет в Bitrix устойчивый маркер ожидания документов;
- дедлайн берётся из первого звонка; если его не назвали — ровно +2 календарных дня;
- дедлайн переживает рестарт Render и восстанавливается из комментария сделки;
- если до дедлайна пришёл хотя бы один входящий пакет документов через Email/Viber/Telegram — первый пуш не отправляется;
- если ничего не пришло — первое напоминание отправляется строго по полю «Предпочитаемый канал связи», без fallback на другой мессенджер;
- в напоминании всегда повторяется конкретный перечень документов по продукту и адрес `mavis.group@mail.ru`;
- эскалации 3/7 или 5/10 дней в v78 не менялись — это следующий CJM-блок.

Тестовый таймер первого пуша: `DOCS_REMINDER_TEST_MINUTES=2`.
После теста обе тестовые переменные удалить.

## Блок 4. Сбор входящих документов — Аттестация + СПК

Подключено к уже существующим каналам:
- Email через IMAP `mavis.group@mail.ru`;
- Viber через Wazzup webhook;
- Telegram через Wazzup webhook.

Логика:
1. Входящий PDF/JPG/PNG/документ связывается с активной производственной сделкой по телефону/email.
2. Для СПК дополнительно автоматически ищется поле сделки с названием вроде «доп.email / дополнительная почта» и учитывается при поиске.
3. Обрабатываются только продукты Аттестация и СПК.
4. Файл сохраняется в существующую папку компании на Bitrix Диске.
5. PDF/изображения анализируются ИИ. Распознаются дипломы, трудовые, аттестаты, документы компании, документы по СИ, Стройдок, техкарты и т.д.
6. По каждой сделке хранится накопительное состояние уже полученных документов в комментарии Bitrix.
7. ИИ сверяет накопленный комплект с конкретным перечнем по продукту и формирует:
   - что получено;
   - чего не хватает;
   - действия по каждому специалисту;
   - что нужно проверить вручную.
8. Эксперт получает уведомление в Bitrix, а полный разбор записывается в таймлайн сделки.
9. Клиент получает один обновлённый статус по выбранному им каналу с конкретным недостающим перечнем.
10. В конце сообщения всегда: `Документы, пожалуйста, направляйте на нашу почту: mavis.group@mail.ru`.

## Безопасный пилот

По умолчанию `CLIENT_DOCS_ALL_DEALS=false`.
Тогда обработчик трогает только:
- `CLIENT_DOCS_TEST_DEAL_ID`, если задан;
- иначе `EXECUTOR_TEST_DEAL_ID` / `LIVE_CHAT_TEST_DEAL_ID`.

Для тестовой ООО «Бобик» достаточно, чтобы текущий тестовый ID был указан в Render. После end-to-end теста поставить:

`CLIENT_DOCS_ALL_DEALS=true`

## Что тестируем

### Тест блока 3
1. Полноценный звонок >60 сек → «Ход работы» отправлен.
2. В комментарии сделки появляется `[MAVIS_DOCS_WAIT_START]` с `sentAt` и `dueAt`.
3. Для ускорения задать `DOCS_REMINDER_TEST_MINUTES=2`.
4. Не присылать документы → через 2 минуты должен уйти первый пуш строго по предпочтительному каналу.
5. Повторить тест: до 2 минут прислать файл → пуш НЕ должен уйти.

### Тест блока 4
1. Отправить с тестового контакта в Viber один документ (например диплом/PDF).
2. В Render должны появиться логи `[client-docs]`.
3. Файл должен появиться в папке компании на Bitrix Диске.
4. В сделке должен появиться комментарий `[MAVIS_CLIENT_DOCS_RECEIVED]` и `[MAVIS_CLIENT_DOCS_STATE]`.
5. Эксперт должен получить уведомление.
6. Клиент должен получить обновлённый перечень того, чего ещё не хватает.
7. Аналогично проверить письмо на `mavis.group@mail.ru`.
