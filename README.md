# MAVIS Bitrix Expert Assistant v7

v7 исправляет ключевую проблему загрузки: в Bitrix24 JS SDK пагинация работает через `result.next(callback)`, а не через `start = result.next()`. Из-за этого v5 загружала только первую страницу — обычно 50 сделок.

## Что изменилось

1. Исправлена пагинация `crm.deal.list`: теперь загружаются все открытые сделки выбранной воронки.
2. `MAX_DEALS=0` по-прежнему означает: без технического лимита.
3. Добавлен ограничитель параллельных запросов при загрузке компаний, контактов, дел, задач и комментариев, чтобы не перегружать Bitrix при сотнях сделок.
4. Закрытые сделки исключаются через `CLOSED=N`, если `EXCLUDE_CLOSED_DEALS=true`.
5. Для руководителя/админа показываются все открытые сделки воронки 28. Для эксперта — только его открытые сделки.

## Рекомендуемые переменные Render

```env
LEADER_USER_IDS=2110,14,2182
ROP_USER_IDS=2156
ADMIN_USER_IDS=2110,14
PRODUCTION_CATEGORY_ID=28
EXCLUDE_CLOSED_DEALS=true
MAX_DEALS=0
ALLOW_ROP_VIEW_ALL=false
```

Если после v7 количество сделок всё ещё заметно меньше, чем в Bitrix, нужно проверить, какие стадии Bitrix считает закрытыми (`CLOSED=Y`). Тогда будем исключать закрытые стадии не через `CLOSED=N`, а через список `STAGE_ID`.


## v7

Добавлено:
- статус проверки передачи по каждой сделке;
- служебная метка в комментарии Bitrix `MAVIS_AI_HANDOFF_AUDIT`, чтобы статус был виден всем пользователям;
- отдельный режим РОП: показывает только сделки с ошибками передачи;
- колонка “Проверка передачи”;
- кнопка “Отметить как проверено”;
- счётчик “Не проверено” вместо временного “Нужно проверить”.

Важно: после нажатия “Записать комментарий” приложение сохраняет результат проверки в таймлайн сделки. После этого сделка перестаёт считаться непроверенной.
