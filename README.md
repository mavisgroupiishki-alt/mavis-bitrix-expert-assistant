# MAVIS Bitrix Expert Assistant v5

v5 исправляет загрузку сделок под логику ТЗ: кабинет должен работать не с последними 50/200 сделками, а со всеми активными открытыми сделками производства, кроме закрытых.

## Что изменилось

1. Добавлена постраничная загрузка всех сделок через пагинацию Bitrix.
2. `MAX_DEALS=0` теперь означает: не ограничивать количество, загрузить все открытые сделки по фильтру.
3. По умолчанию закрытые сделки исключаются фильтром `CLOSED=N`.
4. Для эксперта показываются только открытые сделки, где он ответственный.
5. Для руководителя/админа показываются все открытые сделки выбранной производственной воронки.
6. РОП по умолчанию не видит общий список экспертов, чтобы не смешивать клиентов. Для временного теста можно поставить `ALLOW_ROP_VIEW_ALL=true`.
7. “Без рабочей активности 2+ дня” больше не считает будущий дедлайн активностью. Учитываются: созданные дела, задачи, закрытые задачи, комментарии в CRM и дата создания сделки.
8. Добавлена дополнительная попытка расшифровки стадий через `crm.dealcategory.stage.list`.
9. Верхняя строка приложения теперь поясняет: задана ли производственная воронка, исключены ли закрытые сделки и есть ли технический лимит.

## Рекомендуемые переменные Render

```env
LEADER_USER_IDS=2110,14,2182
ROP_USER_IDS=2156
ADMIN_USER_IDS=2110,14
PRODUCTION_CATEGORY_ID=<ID производственной воронки>
EXCLUDE_CLOSED_DEALS=true
MAX_DEALS=0
ALLOW_ROP_VIEW_ALL=false
```

Для тестирования под РОП, если нужно видеть общий список:

```env
ALLOW_ROP_VIEW_ALL=true
```

После того как в таблице увидите правильный “Воронка ID” у производственных сделок, обязательно заполните:

```env
PRODUCTION_CATEGORY_ID=<ID производственной воронки>
```

Иначе приложение будет загружать все открытые сделки портала по роли пользователя.

## Важно по производительности

Если открытых сделок очень много, первая загрузка может занимать дольше, потому что приложение дополнительно проверяет дела, задачи и комментарии по каждой сделке. Если станет медленно, следующий шаг — вынести сбор данных на сервер и использовать batch-запросы/кэш.
