# MAVIS Bitrix Expert Assistant — v43h VibeCode Whisper

Версия v42 добавляет управляемый пилотный чек-лист прямо во вкладку `ИИ-ассистент` внутри карточки сделки.

Что добавлено:

1. Новая кнопка в блоке `Техническое / тестирование`:
   - `Чек-лист теста`.
2. Чек-лист показывает эксперту порядок проверки ассистента по конкретной сделке:
   - проверка передачи из продаж;
   - ИИ-анализ сделки;
   - ИИ-ход работы;
   - перечень копий клиенту;
   - проверка документов;
   - проверка дедлайнов;
   - оценка ИИ: `ИИ-вывод верный` / `Правка к ИИ`.
3. Чек-лист можно записать комментарием в сделку.
4. В чек-листе отдельно зафиксировано правило пилота: клиенту ничего не отправляется и задачи не создаются без подтверждения эксперта.

Обновление:

1. Загрузить файлы в GitHub.
2. Render → Manual Deploy → Clear build cache & deploy.
3. Открыть карточку сделки → вкладка `ИИ-ассистент`.
4. Нажать `Чек-лист теста`.

Новые переменные Render не требуются.

## v43 — ассистент-исполнитель АТТ на одной тестовой сделке

Режим включается только для сделки `EXECUTOR_TEST_DEAL_ID`. Для теста ООО “Бобик”: `34946`.

Что добавлено:
- кнопка “Автопилот АТТ: звонок → ход работы”;
- кнопка “Найти записи звонков”;
- поиск аудиозаписи звонка в активностях сделки;
- скачивание аудио по URL/файлу Bitrix;
- отправка аудио на `/audio/transcriptions`;
- ИИ-анализ расшифровки по регламенту аттестации организации;
- автокомментарий Кристине в сделку;
- автосоздание задач из ИИ-результата;
- отправка сообщения клиенту по полю “Предпочитаемый способ связи”.

Минимальные переменные:
```
EXECUTOR_MODE=true
EXECUTOR_TEST_DEAL_ID=34946
EXECUTOR_EXPERT_ID=2066
EXECUTOR_PRODUCT=attestation
PREFERRED_CONTACT_FIELD_CODE=UF_CRM_1781189436900
CALL_TRANSCRIPTION_ENABLED=true
TRANSCRIBE_PROVIDER=vibe
TRANSCRIBE_BASE_URL=https://vibecode.bitrix24.tech/v1
TRANSCRIBE_MODEL=bitrix/deepdml/faster-whisper-large-v3-turbo-ct2
TRANSCRIBE_SEND_MODEL=true
```

Важно: v43h использует VibeCode `/v1/audio/transcriptions`. Сначала отправляет model=`bitrix/deepdml/faster-whisper-large-v3-turbo-ct2`; если VibeCode вернет 400 из-за поля model, автоматически повторяет запрос без model, как в официальном примере VibeCode.


# MAVIS Bitrix Expert Assistant — v44 ассистент-исполнитель (полный цикл SPK_ATT)

Что изменилось в v44 (переход от помощника с подтверждением к исполнителю по слайдам теста):

1. Автопилот теперь делает всё за один клик по кнопке «Автопилот АТТ: звонок → ход работы»:
   - проверка передачи из продаж (используется существующая логика `checkHandoff`), при критичных пробелах — автозадача менеджеру, без остановки автопилота;
   - поиск и расшифровка записи первичного звонка (как раньше);
   - ИИ-анализ по единому маршруту **SPK_ATT** (СПК + аттестация организации вместе);
   - отправка хода работы / перечня клиенту через канал из поля сделки (как раньше);
   - **создание внутренних дел** (документы/оплата/дедлайны/следующий шаг) — теперь снова включено, но дела ставятся только сотрудникам MAVIS (`expert`/`manager`/`leader`), никогда клиенту;
   - **движение стадии сделки** — ИИ принимает решение `stage_decision` (двигать/не двигать и куда), код подбирает реальную стадию воронки динамически по названию через `crm.dealcategory.stage.list`, двигается только вперёд по воронке и только при явном решении ИИ; угадывания нет — если подходящей стадии не нашлось, стадия не меняется и это фиксируется в отчёте;
   - финальный комментарий Кристине фиксирует все 6 шагов: передачу, звонок, сообщение клиенту, внутренние дела, стадию, риски.
2. Ограничение пилота прежнее: работает только по `EXECUTOR_TEST_DEAL_ID`.
3. Запуск всё ещё кнопкой (без автотриггера по webhook) — это сознательное решение для текущего теста.

Переменная новая (опционально): `EXECUTOR_LEADER_ID` — кому ставить дела с ответственным `leader`. Если не задана, используется `EXECUTOR_EXPERT_ID`.
