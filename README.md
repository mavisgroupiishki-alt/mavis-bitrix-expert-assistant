# v38 — отправка перечней через Telegram и Viber

Добавлена поддержка двух активных каналов Wazzup одновременно: Telegram и Viber.

Что появилось:
- диагностика Wazzup показывает, какой `channelId` вставлять в `WAZZUP_TG_CHANNEL_ID` и `WAZZUP_VIBER_CHANNEL_ID`;
- отправка перечня клиенту теперь предлагает выбрать Email, Telegram, Viber или несколько каналов сразу;
- сообщения в мессенджеры отправляются только после подтверждения эксперта;
- в сделке фиксируется, куда именно отправлен перечень;
- создаётся задача на контроль получения документов.

Переменные Render:

```env
WAZZUP_API_KEY=
WAZZUP_BASE_URL=https://api.wazzup24.com/v3
WAZZUP_TG_CHANNEL_ID=678ecc61-f4db-4d62-bcb4-0aee75a8839f
WAZZUP_TG_CHAT_TYPE=telegram
WAZZUP_VIBER_CHANNEL_ID=7a4e407e-bece-4ed1-8d85-dc45a9320659
WAZZUP_VIBER_CHAT_TYPE=viber
```

Старые переменные `WAZZUP_CHANNEL_ID` и `WAZZUP_CHAT_TYPE` оставлены как fallback, но для текущей схемы MAVIS лучше использовать отдельные переменные для Telegram и Viber.

## v36 — отправка перечней клиенту

Добавлено безопасное отправление перечня копий клиенту после ручного подтверждения эксперта.

Что появилось:
- кнопка `Отправить перечень клиенту` после формирования перечня;

- используется Wazzup API `POST https://api.wazzup24.com/v3/message`;

- ключ Wazzup нельзя добавлять в GitHub или отправлять в чат.

## v25
Добавлены управленческие эскалации по критическим проблемным сделкам.

Новая кнопка в кабинете руководителя / РОП: **Создать эскалации**.

Эскалация создаётся, если по сделке есть критичный риск:
- просроченное дело или задача;
- ошибка передачи не исправлена 1+ день;
- спорные данные передачи не подтверждены 1+ день;
- одновременно нет следующего шага и нет рабочей активности 2+ дня.

Задача-эскалация привязывается к CRM-сделке, не дублируется, содержит причины, детали, эксперта, менеджера и рекомендуемые действия руководителя.

Дополнительные переменные Render:
- `ESCALATION_RESPONSIBLE_ID` — необязательно, ID ответственного за задачи-эскалации.
- `ESCALATION_AUDITOR_IDS` — необязательно, ID наблюдателей через запятую.


## v26
Добавлен первый безопасный ИИ внутри приложения: кнопка **ИИ-анализ сделки** в карточке сделки.

Что делает:
- собирает данные производственной сделки;
- подтягивает связанную сделку продаж, если ссылка заполнена;
- учитывает услугу, стадию, чек-лист, текущую проверку передачи, дела и задачи;
- отправляет контекст на серверный endpoint `/api/ai/analyze-deal`;
- возвращает структурированный результат: что понятно, чего не хватает, риски, следующие действия, рекомендуемые задачи и черновик сообщения клиенту.

Безопасность:
- клиенту ничего не отправляется автоматически;
- задачи не создаются автоматически;
- результат можно записать в комментарий только вручную;
- `AI_API_KEY` хранится только в Render Environment и не отдаётся в браузер.

Переменные Render для включения ИИ:
- `AI_ENABLED=true`
- `AI_PROVIDER=openai`
- `AI_API_KEY=...`
- `AI_MODEL=gpt-4o-mini`
- `AI_TEMPERATURE=0.2`

## v28 — ИИ в рабочих сценариях

Добавлены отдельные ИИ-сценарии внутри карточки сделки:

- **ИИ-проверка передачи** — проверяет качество передачи из продаж в производство: КП, услуга, сроки, email, пошлины, специалисты, средства измерений, следующий шаг.

## v31 — обратная связь по ИИ и режим обучения
Добавлены кнопки в карточке сделки после любого ИИ-сценария:
- **ИИ-вывод верный** — эксперт фиксирует, что результат можно принимать как корректный.
- **Правка к ИИ** — эксперт оставляет короткую правку: что ИИ понял неверно или чего не хватило.

Оценка сохраняется в комментарий сделки с технической меткой `MAVIS_AI_FEEDBACK`. Это нужно для режима обучения: первые сделки эксперт проверяет и фиксирует качество ИИ-выводов, чтобы потом собрать типовые ошибки и улучшить промпты/логику по продуктам.

Клиенту ничего не отправляется автоматически, задачи не создаются автоматически.

## v34 — улучшенные промпты ИИ по продуктам

Добавлена продуктовая инструкция для ИИ-сценариев. Теперь при ИИ-анализе приложение передаёт модели не только данные сделки, но и правила по продукту:

- СТК / СПК;
- периодика / подтверждение СТК;
- аттестация организации;
- аттестация специалиста;
- ISO / СУОТ / охрана труда;
- подбор специалиста;
- общий сценарий, если продукт не распознан.

ИИ должен строже разделять найденные факты, спорные пункты и риски, не обещать сроки без подтверждения, предлагать задачи с ролями expert / manager / leader и формировать клиентский текст без внутренних управленческих формулировок.

## v37 — диагностика Wazzup

Добавлена кнопка **“Проверить Wazzup”** в карточке сделки. Она вызывает `/api/wazzup/channels`, показывает список каналов и подсказывает, какой `channelId` нужно добавить в Render как `WAZZUP_CHANNEL_ID`.

Переменные Render:

```env
WAZZUP_API_KEY=секретный ключ Wazzup
WAZZUP_CHANNEL_ID=channelId из диагностики
WAZZUP_CHAT_TYPE=whatsapp
WAZZUP_BASE_URL=https://api.wazzup24.com/v3
```

Секретный ключ не попадает в браузер: фронтенд получает только список каналов через серверный endpoint.
