# ИИгорь Agent Core v126 — тест на Бобике

Это новый слой поверх текущего v125. Он **не заменяет** уже работающие Bitrix/Wazzup/акты/почту.

Главное отличие: код больше не говорит ИИгорю «если стадия X и прошло N минут — делай Y».
Код только:
- собирает контекст сделки;
- даёт ИИгорю инструменты;
- ставит safety-границы;
- выполняет решение ИИгоря, если оно разрешено.

## Что ИИгорь читает в v126

- всю карточку сделки и непустые UF_CRM поля;
- текущую стадию и её название;
- компанию и контакт;
- телефоны/email;
- комментарии таймлайна;
- CRM-активности, звонки и наличие файлов;
- связанные задачи;
- другие активные сделки той же компании;
- сохранённые chat-маркеры `[MAVIS_LIVE_CHAT]`, `[MAVIS_CLIENT_DOCS]`, `[MAVIS_DOCS_WAIT_START]`;
- предпочитаемый канал связи.

Ограничение первого прототипа: **прямая история Wazzup через API ещё не загружается**. Если важный ответ клиента есть только в Wazzup и не попал в Bitrix, ИИгорь обязан считать контекст неполным и не фантазировать.

## Безопасный первый тест

После запуска patch:

```bash
node apply_v126_agent_core.js
```

В Render добавьте/проверьте:

```text
AGENT_CORE_TEST_DEAL_ID=38072
AGENT_CORE_ALLOW_EXECUTE=false
AGENT_CORE_ALLOW_CLIENT_SEND=false
```

Deploy.

Проверка статуса:

```text
GET https://<ваш-render>/api/agent-core/status
```

Первый ситуационный анализ Бобика:

```text
POST https://<ваш-render>/api/agent-core/run/38072
```

Никакого сообщения клиенту при этом не уйдёт. В ответе смотрим блок `decision`:
- `situation`
- `goal_now`
- `blocker`
- `evidence`
- `missing_context`
- `confidence`
- `safe_to_execute`
- `action`

## Когда разрешим действие

Только после того как решение по Бобику выглядит адекватно:

```text
AGENT_CORE_ALLOW_EXECUTE=true
AGENT_CORE_ALLOW_CLIENT_SEND=true
```

и вызываем:

```text
POST /api/agent-core/run/38072?execute=1
```

Даже тогда v126:
- исполняет действия только по сделке 38072;
- клиентское сообщение отправляет только при `safe_to_execute=true`;
- требует confidence >= 0.72;
- соблюдает предпочитаемый канал;
- email пока не отправляет;
- жалобы/возвраты/споры должен эскалировать человеку.

## Что будет следующим

После Бобика нужно подключить прямую историю Wazzup к context collector и заменить старые CJM polling-блоки на event wake-ups: входящее сообщение, письмо, документ, изменение сделки, наступление обещанной даты.
